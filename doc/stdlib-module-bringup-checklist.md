# Standard Library Bringup Checklist

This tracks Python standard library modules that unlock a large amount of
ordinary Python code. The list is intentionally biased toward foundational
runtime behavior, imports, common data structures, text handling, files, and
developer tooling.

## Status Legend

- `[ ]` Not started or not assessed.
- `[~]` Partial support. The notes should say what is missing.
- `[x]` Complete enough for normal use in CloverVM.

Use the status marker and the notes column together. A module can be partially
checked off when the common path works but important Python-visible semantics,
edge cases, platform behavior, or APIs are still missing.

Int-subclass overrides are bypassed; custom non-int `__index__` remains unsupported and raises TypeError without callbacks. Existing native-call diagnostics may differ in wording; see [base-conversion limitations](python-deviations.md#base-conversion-builtins-accept-stored-integer-payloads-only). `NoneType.__hash__` provides the CPython 3.14 fixed singleton hash through native and guarded trusted handlers, including dictionary collision coverage. Trusted bootstrap defines `abs` through cached `__abs__` dispatch, with trusted int/bigint/float handlers and inherited bool behavior. Public `bool(object=False, /)` now uses a managed `__new__` and the existing truth protocol, preserving singleton identity, receiver/argument rejection, callbacks, cache invalidation, reentry, and reclamation rooting; C API boolean factories remain separate. Existing NotImplemented truthiness and non-integer length-index coercion deviations still apply. It also covers core object-introspection helpers: `isinstance`, `issubclass`, `getattr`, `hasattr`, `setattr`, `delattr`, `vars`, `callable`, and a limited `dir`. The POSIX `OSError` family and `IOError`/`EnvironmentError` aliases now share native storage with errno-based exact-base construction, filename fields, custom initializer support, and latent ordinary OS attributes; see the documented attribute/protocol deviations. The existing POSIX syscall wrappers use the shared OSError C API bridge. `print` now accepts keyword-only `sep`, `end`, `file`, and `flush` parameters for stdout output, with `file` limited to `None` until stream support exists. `sorted(iterable, /, *, key=None, reverse=False)` builds a fresh exact list using existing iteration and the base builtin stable sort; `min`/`max` support streaming key evaluation, first-item ties, multiple positional arguments, and single-iterable `default` with validation order checked against CPython 3.14.5. Selection builtin keyword matching uses string payloads without subclass hooks or value rehashing; invalid-name diagnostics preserve CPython's comparison/conversion callbacks. Ordinary Python call binding is unchanged. These use existing iteration without sequence-only `__getitem__` fallback or length-hint callbacks, and retain general callable-instance/bound-method callback limitations. `enumerate` and `zip` now provide ordinary lazy native iterator objects with managed callbacks, exact tuple outputs, arbitrary-size enumerate counters, strict zip checking, and exception/reentry recovery checked against CPython 3.14.5. Custom `__index__`, iterator-validation/sequence-fallback dependencies, pickling and specialization remain explicit; see [iterator limitations](python-deviations.md#enumerate-and-zip-use-the-existing-iterator-protocol-subset). `type` remains the VM's builtin class object rather than a fully compatible callable `type(obj)`/`type(name, bases, dict)`. `dir` enumerates stored own namespaces plus class MRO entries; full CPython behavior around custom `__dir__`, metaclass details, descriptors, signatures, streams, and many other builtin functions remains incomplete. Bounded native-backed `bytearray` now supplies mutable storage, indexing/slices, append/extend/clear, integer iteration, all six comparisons and immutable `bytes` copies for the raw-I/O prerequisite. New-only construction, absent reinitialization/subclassing, general index/buffer protocols, encoded strings, additional methods and fatal heap-exhaustion policy remain explicit in [bytearray limits](python-deviations.md#bytearray-provides-a-bounded-mutable-byte-container). |
| [~] | `types` | Shared type names used by frameworks, decorators, inspection, import machinery. | Pure-Python `types.py` exposes reachable runtime aliases (`FunctionType`, `LambdaType`, builtin function/method aliases, `MethodType`, `ModuleType`, `CodeType`, `NoneType`), a minimal `SimpleNamespace`, and `get_original_bases`. `Function.__code__` supplies the live `CodeType`. `SimpleNamespace` repr is checked against CPython 3.14.5: insertion order, subclass names, empty-name omission, string-subclass keys without invoking their hooks, and direct/mutual/container-mediated namespace recursion with exception cleanup. Internal `slotdict.keys()` returns an ordered list snapshot. Repr guarding assumes the current single-threaded runtime, and `__dict__` remains a slotdict rather than a full dict. Constructor and equality improvements are deferred. Missing descriptor/frame/traceback/generator/coroutine/union/generic-alias types, `new_class`, `prepare_class`, `resolve_bases`, `coroutine`, and other APIs remain blocked by callable `type`, richer metadata, descriptors, and broader runtime object exposure. |
| [~] | `operator` | Functional forms of operators used by collections, sorting helpers, libraries. | Pure-Python first slice covers supported arithmetic/bitwise/comparison/identity/truth helpers; `abs` delegates to builtin special-method dispatch, matrix multiplication, item get/set/delete, sequence concat, membership-backed `contains`, identity-before-equality `countOf`/`indexOf`, `length_hint`, CPython 3.14 supported-name `__all__`, and aliases such as `__add__`. Heap integers above the SMI limit remain accepted within platform bounds. General `__index__` support and platform-bound selection for future non-64-bit targets remain deferred. |
| [~] | `collections` | `deque`, `defaultdict`, `Counter`, named tuples, ordered helpers. | Public Python `UserDict` slice, audited against CPython 3.14.5: construction, public `data`, item operations, membership/iteration/length, representation/equality, `get`, live `keys`/`values`/`items`, `update`, `setdefault`, `pop`, first-key `popitem`, `clear`, and exact-base shallow `copy`. | [~] | `heapq` | Heap priority queues and stable bounded selection. | Pure-Python min/max heaps implement positional-only `heapify`, `heappush`, `heappop`, `heapreplace`, `heappushpop` and their `_max` variants using CPython 3.14.5 fallback algorithms. `nlargest(n, iterable, key=None)` and `nsmallest(n, iterable, key=None)` use stable ordinal-decorated bounded heaps, streaming min/max for `n == 1`, and sorting only the retained candidates except for CPython's known-size `n >= len(iterable)` shortcut. Key evaluation follows input order once per consumed item; nonpositive n still performs setup, and the bounded path consumes no input (a reported size of zero can select the sorting shortcut for n=0). Heap arguments must be lists or list subclasses; ordinary subclass hooks run rather than accelerator bypasses. Selection uses existing iterable/call protocols: no sequence-only iteration fallback, length-hint parity, callable-instance or first-class bound-method callbacks. Bounded range arguments remain SMI-sized; general custom `__index__` and int-subclass range coercion are unsupported, while builtin bool n is normalized locally. Iterator validation and builtin sorted/min/max limitations remain dependencies. Regressions cover call contracts, heap invariants, comparison direction, ties/identity, key counts/order, consumption, subclass hooks, callback mutation/reentry and exception identity/partial states. Host fallback differential checks: `python3.14 tests/host/test_heapq_expansion.py`. No compiler repair is included. Exception-message wording is not matched. `merge` and native acceleration remain excluded; no VM changes. |

| [~] | `functools` | Decorators, wrappers, caching, partial application. | Managed streaming `reduce(function, iterable, /, initial=...)`, checked against CPython 3.14.5, including positional/keyword initial, explicit None, identity-preserving empty/singleton results, left-fold ordering, and callback/iterator exceptions. Builtin aliases protect post-import rebinding; rebinding before first import remains unsupported. Existing callable-instance/bound-method, iterator validation/sequence-fallback, and function-introspection limitations remain; argument-binding error wording follows ordinary managed functions, and absent exception-context attributes remain omitted rather than exposing None. No private native module. All other APIs, including partial, wrappers, caching, descriptors, and dispatch decorators, remain unimplemented. |
| [~] | `bisect` | Binary search and maintaining sorted sequences. | Pure-Python `bisect_left`/`bisect_right`, `insort_left`/`insort_right`, and identity aliases `bisect`/`insort`, checked against CPython 3.14.5. Preserves positional/keyword bounds, keyword-only `key`, comparison direction, element-only search keys, original-object insertion, callback order, exceptions, and mutation visibility. General `__index__`, callable-instance and first-class bound-method keys, exact C argument-parser diagnostics, and accelerator-only eager sequence-slot validation/mapping rejection remain excluded. Normal Python comparison dispatch does not repeat a same-type `__lt__` returning `NotImplemented` as the C accelerator does (accepted divergence). Builtin indexing/insertion retains existing VM integer limits; synthetic custom sequences cover large signed-platform bounds without allocating huge containers. No native accelerator or runtime changes. |
| [~] | `itertools` | Common efficient iteration building blocks. | Pure-Python lazy classes implement `chain`, class-level `chain.from_iterable`, finite/infinite `repeat`, `islice`, `starmap`, `compress`, `filterfalse`, `takewhile`, `dropwhile`, `pairwise`, and `count`, using real builtin iteration/call facilities. CPython 3.14.5-attributed interpreter tests cover signatures, construction laziness, consumption order, exception identity/recovery, callback truth tests, reentry, exact tuple outputs, integer boundaries, and floating-step rounding; the expansion tests also run with reclamation at every safepoint and bounded hot loops for JIT-enabled builds. Callable instances and first-class bound methods remain unsupported; callable `bool` predicates depend on builtin bool construction. Broader iterable validation/fallbacks belong to the builtin iterator protocol. Other itertools APIs, repr/pickling/copy/type metadata compatibility, exact refcount-dependent finalization timing, CPython tuple recycling, and `repeat.__length_hint__` remain unimplemented; no native acceleration is included. |
| [~] | `contextlib` | Context-manager helpers used pervasively in tests and libraries. | Pure-Python module now covers `AbstractContextManager`, `closing`, `nullcontext`, `suppress`, and `chdir` on top of current `with` semantics. ## Cross-Cutting Stdlib Notes

- Native extension support now includes helpers for reading tuples and UTF-8
  strings from extension modules, with export-list wiring. This should make
  future native-backed modules less ad hoc, especially modules that need to
  accept structured Python values or text from public wrappers.

### Slice comparisons

`slice` supports `<`, `<=`, `>`, and `>=` through managed field-tuple comparisons
with CPython 3.14.5 identity, callback, reflection, and result-preservation
semantics. Comparison does not normalize indices. See the
[slice comparison contract](slice-support-design.md#implemented-surface).

### UserDict boundaries and VM dependencies

- `stdlib/collections.py` exports only `UserDict`. `Counter`, `defaultdict`,
  `namedtuple`, `deque`, `OrderedDict`, `ChainMap`, `UserList`, and `UserString`
  remain absent. `collections.abc` is not supplied by this module.
- `UserDict.fromkeys` is absent until classmethod binding exists. Union operators,
  `__copy__`, pickling, generic aliases, ABC inheritance/registration, and
  hashability parity with arbitrary user classes are outside this slice.
- `copy()` returns an independent shallow copy for exact `UserDict` instances.
  Subclass calls explicitly raise `NotImplementedError`; preserving subclass
  instance state and avoiding constructor/descriptor effects needs `copy` and
  compatible `__new__`/instance-namespace allocation behavior.
- Construction accepts `None`, builtin dictionaries, UserDict instances,
  keys/getitem protocol objects, and supported iterables of supported two-item
  iterables. Updates accept the same sources except `None`. Keywords follow
  positional input. UserDict and dict sources use class-level iteration ahead
  of `keys()`, including inherited builtin dict iteration; other mappings use
  the keys/getitem protocol. Positional-only names such as `self`,
  `dict`, `other`, and `kwds` remain ordinary data keys. Malformed pairs retain
  error types and prior writes; exact diagnostic text is not CPython-compatible. String
  pair elements and string iteration remain blocked by missing `str.__iter__`.
- Direct method calls and class-level `__missing__` dispatch work. Stored bound
  methods remain unusable as general callables. Callable-instance protocol and
  descriptor-based missing handlers are not part of this slice.
- View objects retain the UserDict rather than its current backing dict. They
  support iteration, length, membership, and representation through subclass
  hooks, including replacement of `data`. Set operators/comparisons, public ABC
  view types/registration, generic aliases, and exact generator suspension
  timing are deferred; Python iterator classes replace generators here.
- Keys/values/items iterators each own terminal state: they close permanently
  after exhaustion or an escaping exception, reject re-entry while active, and
  release mapping/iterator references on close. Normal source exhaustion raises
  plain `StopIteration` with empty `args` and `value is None`, discarding any
  delegated iterator's return value. Keys iteration never looks up values;
  values/items convert lookup-raised `StopIteration` to `RuntimeError`.
  Exception chaining (`raise ... from`, `__cause__`, `__context__`) remains
  a general VM gap: the wrapped error type/message is supported, but its original
  StopIteration is not exposed as a cause. Eager key-iterator creation retains
  the existing generator suspension-timing limitation.
- A separate VM lowering gap was observed while implementing iterator cleanup:
  exceptions from a `return` expression inside `try/except/finally` can bypass
  that function's except handlers. The iterators evaluate delegation/lookup into
  a local inside the protected body and return after cleanup. A general codegen
  repair remains outside this slice.
- Equality accepts UserDict and builtin dict operands, honoring `items()`
  overrides and returning `NotImplemented` for other operand types. Supporting
  arbitrary registered Mapping operands needs `collections.abc`/`abc`.
  UserDict materializes `items()` into builtin dicts and delegates to structural
  dict equality. Stored hashes avoid additional user hashing during comparison,
  including nested dict payloads. General recursion-limit enforcement is absent:
  deeply nested or cyclic comparisons are outside the supported slice and may
  exhaust the VM stack rather than reliably raising `RecursionError`.
- `UserDict.__iter__` delegates to `iter(data)`, honoring the backing object's
  `__iter__` rather than its `keys()` override. Updates from dict/UserDict use
  iteration; other mappings retain the `keys()` protocol. Builtin dict iteration
  reuses the existing live key iterator. Its permanent exhaustion, release of
  the source on exhaustion, same-size key-change detection, and length hints
  remain deferred iterator-contract gaps.
  Deletion delegates directly to dict; lookup, deletion, and missing-pop errors
  now retain the original key in `KeyError.args` through generated and native paths.
- Compatibility tests are split across small interpreter source files to stay
  within the 256-entry per-code-object global-read cache limit. They are also
  runnable against CPython 3.14.5; the separate `*_limits.py` file checks only
  CloverVM's intentional reduced surface. No upstream test text is copied;
  module adaptations retain attribution to CPython's collections/mapping code.
- The previously recorded frame assertion is resolved by preserving and checking
  both membership operand shapes during cache replay. A warmed string-key dict
  handler had been reused for other needle shapes, entering general hashing
  through an invalid trusted path. This affected direct and expanded calls.
  UserDict's expanded-call error tests are restored; `membership_cache_replay.py`
  covers changed needle shapes, callback hashing/equality, nested calls, and
  exception propagation. This no longer blocks the UserDict slice.
